# More Match Points

Simple, mobile-first site for More Match Points: 1-on-1 private tennis lessons with Lucas Oskwarek (PTR Certified) from Middlebury, Southbury and Greater Waterbury through Newtown, Monroe, Redding and Danbury, CT.
Static HTML generated by `build.py` from `site.json`, published by GitHub Pages from the `main` branch root.

Live: https://morematchpoints.com/ (custom domain; `CNAME` is written by `build.py` from `base_url`)

## Edit the text

All words on the site live in `site.json` (keys starting with `_` are notes, not shown on the site):

- `name` (brand: header wordmark, titles, share image, manifest, footer, search listing), `brand_sub` (line under the wordmark), `footer_line`, `coach`
- `hero_eyebrow`, `hero_lines` (big headline, one entry per line), `hero_highlight` (how many last lines are optic yellow), `hero_intro`: the hero
- `stats`: the credentials strip under the hero (#1 Singles, SWC, Top 30 USTA CT, PTR), also on /about/; the home strip links to /about/
- `experience`: the experience cards on the **About Lucas** page (/about/, flyer + resume wording), `about_intro` its intro; `why` keeps the flyer's list for reference
- `steps`: "How it works"; `price_points`: the pricing card list
- `area_line` (hero + footer), `og_area` (share images) and `area_cities` (every town, for search engines): lesson area
- `title`, `meta_description`: home page search title and description (also link previews); `description` is the longer business description in the structured data
- `area_title`, `area_intro`: the home "Where I teach" section; `faq` and `home_faq_count`: the FAQ (see below)
- `book_title`, `book_text`: the booking section

The lesson request form is the only contact method on the site; no phone number or email address is published.

## Rebuild

```
python3 build.py                 # writes index.html, tennis-lessons/, faq/, thanks/, 404.html, sitemap.xml, robots.txt, site.webmanifest
python3 build.py --check         # exits 1 if anything is out of date; run before committing
BUILD_DATE=2026-10-22 python3 build.py   # optional: pin the sitemap date so rebuilds don't create date-only changes
python3 tools/check_seo.py       # JSON-LD parses, schema sanity, unique titles/descriptions, canonicals, word counts
git add -A && git commit -m "Update site" && git push
```

Styles are in `src/style.css` and the small script in `src/site.js` (both inlined by the build). Court and area graphics are SVG drawn in `tools/art.py`.
The script only adds the scroll reveal and hides the sticky mobile button while the form is on screen. Everything is visible without JavaScript, and all motion is off under "reduce motion".

## Change the price

The price is set in one place: `"price"` in `site.json` (whole dollars, currently `45`). Any other text in `site.json` or `towns.json` writes `{price}` and the build fills it in, so the hero, price cards, schema Offer, meta descriptions, FAQ and town pages all follow.

1. In `site.json`, set `"price"` (e.g. `50`). Don't type a dollar amount anywhere else; use `{price}`.
2. Run `python3 tools/make_brand.py` so the share images (`images/og-image.png` and `images/og/*.jpg`) show the new price.
3. Run `python3 build.py && python3 build.py --check`, then commit and push.

## Lesson request form (FormSubmit)

- The endpoint is `form_endpoint` in `site.json`, currently FormSubmit's random-string alias (activated 2026-10-22), so no inbox address appears in the page.
- **Activation:** FormSubmit sends a one-time activation email to that address on the first real submission. Nothing is delivered until someone clicks **Activate** in that email.
- After activation, FormSubmit offers a random-string alias. Swap it in by setting `form_endpoint` to `https://formsubmit.co/<alias>` and rebuilding, which keeps the address out of the page source.
- Fields sent (shown in the email table): `name`, `phone_or_email`, `skill_level`, `town`, `preferred_times`, `message`.
  Hidden: `_subject` (`form_subject`), `_template=table`, `_captcha` (`form_captcha`), `_next` (the `/thanks/` page) and the `_honey` spam trap.
- Skill level and town choices are `skill_levels` and `form_towns` in `site.json`.
- Set `form_endpoint` to `null` to hide the form.

## Header menu

The header has How it works, Pricing, **Locations** (every town page + All locations) and **About** (About Lucas, FAQ).
On desktop, Locations and About are disclosure buttons (click/Enter/Space to open, arrow keys move through the links, Escape or a click outside closes). On phones a menu button opens a full-screen panel (Escape closes and returns focus to the button; the page behind doesn't scroll), and Locations/About expand inside it.
Without JavaScript the menu is a plain row of links (Locations goes to /tennis-lessons/, About to /about/). The behaviour is in `src/site.js`; menus are built from `towns.json` by `nav()` in `build.py`.

## Town pages (local SEO)

`towns.json` drives `/tennis-lessons/` (index) and one page per town at `/tennis-lessons/<slug>/`, e.g. `/tennis-lessons/middlebury-ct/`.
Each town has `name`, `slug`, `lat`/`lon` + `label` (position on the area map), `lede` (intro, also the search description), `body` (paragraphs, 150–300 words in total and different for every town) and `courts`.

- **Courts:** only list a court that an official town or parks & recreation page names. Put the official page(s) in `_court_sources` (kept for reference, never shown on the site). If nothing official was found, set `"courts": null` and keep the copy general (Middlebury currently).
  The pages never promise a facility: lessons happen at a local public court arranged when you book.
- Don't add distances, partnerships or claims that aren't true.
- `where_note` replaces the "Where lessons happen" box when a town's courts don't allow private lessons (Newtown, Monroe and Redding town courts only allow lessons run by their parks departments; sources in `_court_sources`). `_fact_sources` records where other local facts (e.g. Southwest Conference schools) were checked. `map` + `label` place the town on the "Where I teach" diagram.
- To add a town: add an entry (copy an existing one), add it to `area_cities` and `form_towns` in `site.json`, run `python3 tools/make_brand.py` (makes `images/og/<slug>.jpg`, the town's share image), then rebuild and run `python3 tools/check_seo.py`.
- Every page gets a canonical URL, breadcrumbs (on the page and as schema), a sitemap entry with `lastmod`, and links from the home "Where I teach" section and the footer.

## FAQ

`faq` in `site.json` (list of `q`/`a`) feeds `/faq/` (with FAQPage structured data) and the first `home_faq_count` questions on the home page.
**Rain answer:** "rescheduled at no charge, agreed when booking". Confirm this is the policy you want before relying on it, and edit the `a` text if not.

## Reviews

`reviews` in `site.json` is empty on purpose. While it is empty, nothing shows on the site and no review structured data is added.
Only add a real review from a real student or parent, with their permission to publish it:

```
"reviews": [
  {"name": "J.M.", "text": "Their words, unedited.", "date": "2026-11-05"}
]
```

Use first name + last initial or initials (whatever they agreed to), their actual words, and the date they gave it. Never write or edit a review yourself. Then rebuild.
A "Students say" section appears above the FAQ. No star ratings or review schema are added, because Google ignores self-published reviews for local businesses.

## Design

- Colours: midnight navy `#0a1128`, raised navy `#111b3a`, court blue `#1d43a6`, optic yellow `#d7f205`, paper `#f4f5ef`, clay `#a3461f` (small labels on paper), white.
  Optic yellow is only used on navy, or as a fill with navy text (buttons, badges). Never use it as text on white or paper (fails AA contrast).
- Fonts (self-hosted in `fonts/`, OFL licences alongside): **Anton** (display, `anton-latin.woff2`, 18 KB) and **Inter** variable 400–800 (body, `inter-latin-var.woff2`, 47 KB). Both are Latin subsets from Google Fonts with `font-display: swap` and preloaded.

## Add Lucas's action photo

The hero currently shows a court-and-ball illustration on purpose. To use a real photo:

1. Save a portrait action shot (about 1200×1400, under 300 KB, EXIF/GPS removed) as `images/lucas-action.jpg`.
   To strip metadata and resize: `python3 -c "from PIL import Image; im=Image.open('in.jpg'); im.thumbnail((1200,1400)); im.convert('RGB').save('images/lucas-action.jpg', quality=82)"`
2. In `site.json` set `"hero_photo": "images/lucas-action.jpg"` and `"hero_photo_alt": "Lucas Oskwarek hitting a forehand"` (describe the actual photo).
3. Run `python3 build.py && python3 build.py --check`, commit and push. Set `hero_photo` back to `null` to return to the illustration.
